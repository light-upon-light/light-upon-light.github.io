Server-rendered, not built at runtime with document.createElement: every value here (quran.md's short_title, page.quran_section, its label, this page's own short_title) is fixed at build time, so there was nothing that actually needed a browser to compute. The previous version's stated reason for going through JS was keeping the markup out of .page__content, since Lunr indexes that container verbatim (search_full_content in CLAUDE.md) and a static link there would become the truncated search snippet for every hit on the page. `, which is what contains .page__content. The end-of-article return link (a.back-to-quran-link, built in footer/custom.html) is deliberately NOT handled here.
